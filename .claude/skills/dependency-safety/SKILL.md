# Dependency Safety — стоит ли ставить пакет

Правило проекта (`docs/04-repo-review.md`): **любая новая production-зависимость проходит эту
проверку до установки.** Инвариант `AGENTS.md`: без явного одобрения владельца её не добавляют вообще.
Скилл даёт основание для решения, а не право его принять.

## Сначала — нужен ли пакет

1. Решается ли задача стандартной библиотекой, платформенным API или тем, что уже стоит?
   `Intl.NumberFormat` вместо библиотеки форматирования, `crypto.randomUUID()` вместо `uuid`,
   `structuredClone` вместо `lodash.clonedeep`.
2. Сколько кода мы на самом деле используем? Пакет ради одной функции на десять строк — не зависимость.
3. Это dev- или production-зависимость? К dev требования мягче: она не едет к пользователю.

Если пакет не нужен — остановиться здесь. Это самый частый исход.

## Проверка

```bash
npm view <pkg> version time.modified maintainers license repository.url
npm view <pkg> dependencies
npm audit --package-lock-only          # после добавления в lock, до коммита
```

| Сигнал | Смотрим | Красный флаг |
|---|---|---|
| Живость | дата последней публикации | молчание больше года при активных открытых issue |
| Сопровождение | число мейнтейнеров, активность репозитория | один мейнтейнер и заброшенный репозиторий |
| Граф | сколько транзитивных зависимостей тянет | десятки пакетов ради одной функции |
| Уязвимости | `npm audit` | high/critical без выпущенного фикса |
| Лицензия | поле `license` | отсутствует, GPL/AGPL или своя формулировка |
| Вес | размер бандла для клиентского кода | заметная доля бюджета страницы |
| Имя | опечатки, похожие имена | тайпсквоттинг: `momment`, `lodahs`, `reakt` |
| Установка | наличие postinstall-скриптов | произвольный код при установке |

## Особое внимание в этом проекте

- **Клиентский вес** — конфигуратор уже несёт three.js и текстуры. Для кода, попадающего в браузер,
  вес пакета сверяется с бюджетом страницы, зафиксированным в треке M2.
- **Оплата и авторизация** — только официальные SDK провайдеров. Обёртки третьих лиц вокруг
  платёжных API не ставим: через них проходят деньги и персональные данные.
- **3D и геометрия** — прежде чем тянуть библиотеку, проверить, не решается ли это тем,
  что уже написано в `_source/prototype/Frame3D.js`: там процедурная геометрия без внешних помощников.

## Вердикт

Короткий блок в ответ, без отдельного файла:

```text
пакет:        <имя@версия>
зачем:        <задача в одну строку>
альтернатива: <что в стандартной библиотеке / уже стоит; почему не подошло>
живость:      <последняя публикация, мейнтейнеры>
граф:         <N транзитивных>
audit:        <чисто | N уязвимостей: severity>
лицензия:     <...>
вес:          <для клиентского кода>
вердикт:      СТАВИМ | НЕ НУЖЕН | РИСКОВАННО — <одна причина>
```

`РИСКОВАННО` — не запрет, а повод показать вердикт владельцу до установки.
Решение об установке production-зависимости остаётся за ним.
