# RAKURS furniture — сайт мастерской стальной мебели

E-commerce для мастерской стальной мебели (Тбилиси). Ключевая фича — **визуальный конструктор**
изделия с живой 3D-моделью и мгновенным расчётом цены.

## Статус

Спринт до 24.09.2026 — закрытый показ конфигуратора (Cube и Deska), заявка в Todoist,
два языка ka/ru. Объём и границы — `docs/handoff-prompt.md`.

Собран каркас: Next.js 15 + TypeScript, Tailwind v4 на токенах ДС «Каркас»,
локальные шрифты, next-intl (ka по умолчанию, ru), четыре компонента дизайн-системы.

Стек зафиксирован владельцем 06.09.2026 (подробности и обоснования — в `docs/04-repo-review.md`):
**Next.js + TypeScript, Tailwind + shadcn/ui, Three.js через react-three-fiber,
Supabase, Vercel, next-intl, Vitest + Playwright.** Оплата — сменный модуль
(эквайринг банка Грузии + крипта), Stripe в регионе недоступен.

## Запуск

```
npm install
npm run dev     # http://localhost:3000/ka — грузинский, /ru — русский
npm run check   # быстрый цикл: typecheck + lint + юнит-тесты
npm run verify  # всё разом: check + сборка + Playwright
npm run build
```

`npm run verify` — единственная команда, которой проверяется всё. `check`
оставлен отдельно для быстрого цикла: он идёт полсекунды, а `verify` около двух
минут, потому что собирает проект и гоняет браузер.

`npm run e2e` сам поднимает `next start` на порту 3100. Прогоняется в трёх
раскладках: 1280, 768 и 360 с эмуляцией касаний.

Конфигуратор с 3D — на главной, якорь `#configurator`.
Витрина компонентов дизайн-системы для визуальной сверки с прототипом — `/ka/ui`, `/ru/ui`.
Страница витрины рабочая, в продакшен не идёт.

`npm run build` пишет в `.next-build`, чтобы не затирать `.next` работающего dev-сервера.

### Приём заявок

Заказ сохраняется в PostgreSQL Supabase через серверный маршрут `/api/orders`. До записи сервер
повторно проверяет параметры, пересчитывает цену и отвергает расхождение с суммой на экране.
Повторная отправка с тем же ключом не создаёт дубль.

Перед первым реальным заказом владелец создаёт проект Supabase, применяет
[`supabase/schema.sql`](supabase/schema.sql) в SQL Editor и задаёт в `.env` или переменных Vercel:
`NEXT_PUBLIC_SUPABASE_URL` и `SUPABASE_SECRET_KEY`. Секретный ключ `sb_secret_…` — только для сервера;
в клиентский код и `NEXT_PUBLIC_*` он не попадает.

Без этих двух переменных форма возвращает ошибку и честно говорит об этом клиенту: тихо потерянная
заявка хуже отказа. Todoist остаётся возможным уведомлением мастеру на следующем этапе, но не
хранилищем заказов.

## Пайплайн

```bash
open docs/pipeline.html
```

Три фазы: **Фундамент** (3–5 дней) → **MVP** (~5–7 недель, ключевой этап) → **Полная версия**.
Внутри — интерактивная диаграмма Ганта: 75 рабочих вечеров, связи между задачами,
критический путь, внешние ожидания (ответы владельца, фото, переговоры с банком).
Граница MVP проведена по прототипу: всё, что Claude Design показал на экране, работает
по-настоящему. Формальная приёмка — чек-лист паритета из 21 пункта. Отметки в странице
сохраняются в браузере.
