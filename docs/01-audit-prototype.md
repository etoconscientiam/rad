# Аудит исходников: прототип «Ракурс» (RAKURS furniture)

Дата: 2026-09-16. Источник: `_source/Прототип конфигуратора с 3D.zip` → распакован в `_source/prototype/`.

## Что это на самом деле

Это **не готовая статика**, а экспорт прототипа из **Claude Design** (формат `.dc.html`).
Страница рендерится не браузером напрямую, а рантаймом:

- `support.js` (1911 строк) — DC-рантайм: парсит `<x-dc>`-шаблон, `{{биндинги}}`, `<sc-if>`, `<x-import>`,
  подтягивает с CDN **React 18.3.1 + ReactDOM + @babel/standalone** и рендерит на клиенте;
- `_ds/karkas-steel-design-system-.../_ds_bundle.js` — скомпилированный бандл дизайн-системы (13 компонентов);
- `STAL Prototype.dc.html` — сам экран: 380 строк разметки-шаблона + 400 строк логики в `<script type="text/x-dc">`.

**Вывод:** взять файлы «как есть» и выложить на хостинг нельзя (рантайм демо-уровня, Babel в браузере,
всё в одном файле, нет SEO/SSR/роутинга). Но всё содержимое **полностью переносимо** — логика и стили
читаемые, не минифицированные. Это отличная спецификация + готовый код 3D, а не мусор.

## Проверено вживую

Прототип поднят локально (`tools/serve-prototype.sh`) и отрендерен в headless-браузере:
главная + конструктор работают, Three.js-канвас строит каркас, слайдеры/сегменты/свотчи живые,
цена пересчитывается, переключение языков KA/EN/RU работает. Скриншот снят, всё соответствует макету.

## Дизайн-система (13 компонентов)

`Button`, `IconButton`, `Card`, `Price`, `StatusChip`, `OrderTimeline`, `Toast`,
`ColorSwatches`, `Input`, `SegmentControl`, `SizeSlider`, `Icon`, `OrdersTable` (админка).

Исходных `.jsx` в архиве нет — только скомпилированный бандл, но он не минифицирован,
разбит по файлам с комментариями, восстанавливается в JSX механически.
Токены (`tokens/*.css`) переносятся без изменений.

**Чего в архиве нет** (хотя readme на них ссылается): `ui_kits/`, `guidelines/`, `components/*.jsx`, `SKILL.md`.
Если у заказчика есть полная папка дизайн-системы — её стоит запросить, это сэкономит время.

## Что уже реализовано в прототипе

- **Экраны:** главная (hero + конструктор + «как это работает» + работы + футер), корзина/оформление,
  экран оплаты (успех/ошибка), трекинг заказа со статусами.
- **Конструктор:** 5 моделей (Cube, Deska, Pats, Chestable, Stella), слайдеры с числовым вводом,
  сечение профиля, цвет металла, цвет ЛДСП, расширение ящика, количество.
- **3D:** живая перестройка геометрии под размеры, текстуры дерева, тень-контакт, orbit + zoom.
- **Прайсинг:** метраж профиля, площадь ЛДСП, вес, срок изготовления, доставка по количеству.
- **i18n:** три полных языка — ka / en / ru (грузинский по умолчанию), запоминается в localStorage.
- **Корзина:** добавление, редактирование позиции, удаление, пересчёт итога.

## Чего нет и что придётся строить с нуля

Бэкенд целиком: каталог/цены в БД, заказы, платёжный шлюз (грузинский банк), уведомления
(Telegram в прототипе — только надпись), админка (есть только компонент таблицы), почта/SMS,
аналитика, SEO, реальные фото товаров, юридические страницы, счёт/накладная.

## Риски и узкие места

1. **Прайсинг захардкожен** в прототипе (`RATES`, `LDSP_RATE`, +40 покраска, +60 работа).
   Для продакшена это должно ехать с бэкенда, иначе цены правятся только релизом.
2. **Расчёт цены на клиенте** — его обязательно надо дублировать на сервере при создании заказа.
3. **Three.js через `import()` с unpkg** — в продакшене ставим локально как npm-зависимость.
4. **Текстуры 3.7 МБ PNG** — обязательна оптимизация, иначе конструктор будет грузиться секундами.
5. **Грузинский язык по умолчанию** — надо подтвердить (в прототипе `lang: 'ka'`).
6. **Расхождения с ТЗ из репозитория** (языки, шрифт, типы изделий, покраска) разобраны
   в `docs/04-repo-review.md` — их надо развести до старта вёрстки.
