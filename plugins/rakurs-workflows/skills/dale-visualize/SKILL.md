# Dale Visualize

Use only when a visual materially clarifies relationships that prose or a short
list would obscure. Do not create a visual merely because a response has several
parts.

Choose the smallest suitable medium available in the current environment:

- an inline chart for measured data;
- Mermaid in Markdown for flows, sequences and simple hierarchies;
- a native diagram, schema, or mockup editor when the request needs that
  artifact;
- a self-contained HTML page only for a rich standalone narrative with several
  connected visuals.

Use supplied data and approved design tokens; never invent points, omit material
gaps, or obscure uncertainty. Label units, axes and assumptions. State what
error bars represent when they are present. For a repository artifact, validate
that the chosen format renders in its intended viewer and link the created file
in the handoff.
